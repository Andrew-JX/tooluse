# 常见失误

## 迁移错了东西

- 把样本页面的版式、组件构成和图表类型整套搬到新页面,只换了文字和数字,结果两个不相干的产品长得一模一样。
- 顺手把样本的功能也带过来:目标页面只服务一种语言的读者,却多了语言开关;没有时间维度,却多了时间范围筛选。
- 先照着样本搭好版面,再回头找理由,而不是先列出这个页面要回答的问题。
- 增强层自带一套现成外观(轨道底色、圆角、按钮内边距、提示浮层皮肤),于是页面照着这套皮长,不同产品又出现同一种控件。外观留给宿主,增强层只留怎么动。

## 手感做坏了

- 高亮只换 class,切换是瞬移;补一个滑块又只过渡了位移,宽度仍然跳变。
- 滑块首帧没跳过动画,页面一加载就从最左边飞到当前项。
- 改写按钮文字后只挂了一帧回调去重量,页面在后台标签页时那一帧不触发,回来看到滑块停在旧位置。
- 滑块位置按 `offsetLeft` 减 `paddingLeft` 推算,宿主换了 padding、border 或 box-sizing 之后错位几个像素,查起来像"只是差一点"。
- 入场错峰没封顶,两百个元素的最后一个等两秒才出现,读起来是卡顿不是错落。
- 展开和收起共用带过冲的 ease-out,收起时先甩一下再停。
- 数字滚动没做中断:新数据来了旧的 `requestAnimationFrame` 还在跑,两个循环同时写一个节点;起点又取的是上一次的目标值,画面从当前 43 直接跳到 100 再往 200 滚。

## 越过了增强层的边界

- 增强层自己监听点击、自己改选中态,再回调通知业务。业务请求失败或外部改了状态时,视觉和真状态分叉。
- 用 `transform: scale()` 做按压反馈,把宿主元素原有的 `translate` / `rotate` 一起覆盖掉。要组合就用 `scale` 这类单独的变换属性,并记得过渡列表也要跟着改。
- `prefers-reduced-motion` 只在 CSS 里兜了底,JS 写的数字滚动照样滚;或者把兜底写成全页规则、或写成容器内的后代通配符,顺手把宿主自己的 accordion、modal、toast 全接管了。
- 运行时是全局单例:第二次初始化覆盖了第一个作用域的 root 和主题配置,resize 监听只增不减,已卸载节点还留在重测量列表里。
- 浮层用 `position: fixed` 配视口坐标,却把节点插进容器内;容器一旦有 `transform`、`filter` 或 `contain`,包含块就变成容器,定位全错。

## 主题与安全

- 把 CSS 变量读进 JS 写死成颜色,切主题后图形留着旧色;用 `light-dark()` 之后读出来更是一段未解析的字符串。
- 深色令牌声明两遍后只改了其中一份,某个组合下颜色对不上。
- 主题写进 `localStorage` 时用了通用键名,同源下另一个项目把它改了;或者用户从没选过就先写入一个值。
- 采集来的名字直接拼进 `innerHTML`,标签成了注入点。

它们是这些规则的反例,不扩张本 skill 的适用范围。
