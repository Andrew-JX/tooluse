# Tooluse Skills

这是一组把验收、执行、审查、静态站部署和工作结账写成可复用规则的 Skills。它们约束证据怎么产生、怎样冻结、由谁裁决，也把一次真实部署中验证过的安全边界压成模板；不替代产品判断、团队权限或真实用户验收。四个公开 Skill 随本站仓库维护；`work-skill` 的唯一源码在私人本地工作系统维护，本站只保留公开说明。

## 这是什么

- `acceptance-author`：在实现前起草、反证并冻结可证伪的验收判据。
- `evidence-bound-executor`：按冻结契约实施，并交接能被独立复核的证据。
- `evidence-led-reviewer`：从仓库事实重建候选实现，审判据、查盲区并按实际影响定级。
- `deploy-static-site-to-tencent`：为静态站生成 GitHub Actions、受限 SSH 发布脚本和部署密钥安装器，执行归档校验、原子切换、回滚与 HTTPS 健康检查。
- `work-skill`：用接任务、卡住、任务收尾、日终周终四个入口整理脱敏的工作事实。

四个公开 Skill 可从本仓库安装到用户级或项目级 Skills 目录。不支持 Skills 时，审查角色使用 `evidence-led-reviewer/assets/reviewer-role-prompt.md`，其余流程直接使用对应 `SKILL.md`。`work-skill` 不从本站仓库分发；私人环境通过用户级目录联接加载其唯一源码，尚无公开安装地址。

## 状态词

- **正在使用**：已经进入稳定的日常使用，并有真实任务证据。
- **试用后保留**：真实试用已经结束，决定保留，但不是当前高频流程。
- **试用中**：正在真实任务中试跑，长期价值和边界尚未定型。
- **已卸载**：安装或试用过，之后已从当前环境移除。
- **尚未实测**：只有资料核对、结构检查或虚构干跑，没有真实批次证据。

五个自建 Skill 目前全部是**尚未实测**。其中四个公开 Skill 的源码随本站仓库维护，`work-skill` 在私人本地源维护；存放位置变化不构成真实使用证据。`deploy-static-site-to-tencent` 所依据的本站部署机制已经真实跑通，但新 Skill 尚未在第二项目调用，不能把机制证据冒充为 Skill 的复用与触发证据。状态只能由真实使用结果升级，不能因为规则写完、构建通过、目录迁移或一次自审就改动。

## 已知边界

### 闭环

规则的输入全部来自同一个人的项目、窗口和记忆。这套体系可以带着完整证据链整体一致地错，而系统内几乎没有信号源能发现。唯一验证过有效的外部输入是用真实数据使用运行中的产品。

### 幸存者偏差

每条规则都对应一次被抓住的事故。没被抓住的事故不产生规则，也没有机制让它们浮出来。`blind-spots.md` 是形状级泛化，是对这条的部分缓解，不是解决。

### 依从性未验证

执行侧依赖 Skill 自动加载；人侧的第①步和第⑨步没有任何触发器，纯靠人想起来，而这两步恰好是唯一防止判据本身写错的两步。

### 触发准确率未测

`description` 写坏的 Skill 要么永不触发，要么处处触发；两种情况都没有量过。

## 不适用范围

一晚上内、单模块、可回滚且不涉及安全、数据、权限或发布的小活，验收、执行、审查与工作结账 Skill 都不触发。写一句可证伪的判据、完成后检查真实 diff 即可；`deploy-static-site-to-tencent` 仅在静态站需要把 GitHub push 接到腾讯云 nginx 时触发，不用于后端、数据库或多服务部署。风险高时不因改动小而跳过完整流程。
