# 文档目录与生长触发条件

每一份文档只在它的触发条件满足之后才写。提前写出来的是空壳，而空壳在形式上已经宣称自己是权威。

**本页所有触发条件都以 SKILL.md 第 1 节的仓库归属判断为前提**：不是你主导的项目，下面一份都不新建。归属这条规则只写在 SKILL.md，此处不复述。

## 起始集（四份，归属确认之后写）

### `AGENTS.md`

**装**：协作规则、目录清单、指向索引的一行、机器验证命令的名字。
**不装**：教程、技术栈介绍、任何随实现变化的描述。

它是唯一一份被无条件读取的文档，所以要短——放不下的东西挪进 `docs/` 并在索引里登记。「多短算短」没有门禁守得住，只有一个诊断信号：`wc -l AGENTS.md` 超过 80 行就该往外挪了（脚手架骨架 19 行，一份装满协作规则与目录清单的实测在 76 行）。

### `docs/INDEX.md`

三栏：路径、权威范围、何时读。见 SKILL.md 第 3 节。

**权威范围这一栏最容易被省掉，也最不能省。** 没有它，两份文档会各自宣称同一件事，而读者无从判断该信哪份。

### `docs/decisions.md`

**装**：为什么选了这条路、放弃了什么、当时的约束、什么条件下这条决策应当重新审视。
**不装**：代码已经说清楚的事。

被推翻时不要删原节，追加一节说明推翻的理由并标注前节作废。被推翻的理由本身是后来人最需要的信息——它解释了为什么显而易见的做法行不通。

### `docs/progress.md`

四栏：改了什么、依据、证据、未验证。

「未验证」是全部价值。事后查账本，查的是**当时知道什么、什么没验证**，不是当时做成了什么。

## 按触发条件生长

| 文档 | 触发条件 | 一旦写了，必须同时做的事 |
|---|---|---|
| API 契约 | 对外路由超过 5 条 | 配双向门禁：文档里的每个端点在代码里存在，代码里的每个端点在文档里存在，例外走一个显式的白名单常量 |
| 数据模型 | 出现第二张迁移表，或第一条不可逆迁移 | 写清哪些迁移不可回滚，以及回滚时的替代路径 |
| 部署 runbook | **第一次生产部署之前** | 命令要在干净环境照着逐条跑通一遍才算写完；写清哪些步骤需要单独授权 |
| 上线自检单 | **第一次生产部署之前** | 每条自检写成可判定的观察，不写「确认正常」 |
| 领域文档 | 同一个领域被追问到第三次 | 在索引里写清它和相邻文档的边界 |
| 账本归档 | `progress.md` 超过约 500 行 | 归档目录在索引里登记；不要把历史塞回入口文档 |
| 目录清单门禁 | 顶层目录超过 6 个 | 双向：清单里的目录存在且非空，存在的目录写进清单 |
| 合规文档 | 出现跨境数据、备案、许可证或用户协议 | 标明适用司法辖区和复核日期 |

部署相关的两份是唯一带「之前」的条件——它们在事故发生后补写，价值会掉一大半，因为那时你已经在凭记忆重建当时的状态。

## 不该写的文档

**快照型文档。** 任何名字像「当前实现」「现状」「架构现状」的文档。它必然落后于代码，而它的形式暗示自己是权威，结果是指挥人去修改正确的实现。当前状态由代码和门禁回答。

**同一事实的第二份副本。** 如果一个事实已经在别处维护，这里写引用，不写内容。重复副本是最大的漂移来源：改了一处，另一处立刻变成假话，而且没有任何信号提示。

**每个小 bug 的独立长文。** 一行账本 + 一个回归测试就够了。测试是不会过期的那部分。

## 复核

文档没有 owner、没有更新触发器、也没有门禁时，它一定会烂。给每份文档至少配一样：

- 机器门禁（最强，但只能守可判定的不变量）
- 明确的更新触发器（「改路由时同步这份」）
- 复核日期 + 过期条件（「超过 90 天未复核则不得作为事实引用」）

三样都没有的文档，删掉比留着强。
