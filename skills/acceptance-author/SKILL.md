# Acceptance Author

判据是整条流程的单点。第⑥⑦⑧⑨步全部以它为尺子，所以判据错了，下游四层会一致地给出绿灯并附上完整证据链。这份 skill 只做一件事：在开工前把判据写到能被证伪，然后冻结。输出语言跟随用户。

## 冻结规则

- 判据由规划者在开工前写定并冻结。执行方不得新增、删除、放宽或改写。
- 执行方发现判据有问题：停下报告，由规划者改写并进入下一轮，不自行调整。
- 使用三个独立锚点：`contract SHA` 保存获批判据，`baseline SHA` 标记实现起点，`candidate SHA` 标记候选实现。先冻结前两个，再开始实现。
- `candidate SHA` 必须能追溯到已批准的 contract；它若改动契约文件，原批准自动失效，退回重新冻结。只存在于对话里的判据等于没有判据。

## 写完之后逐条过这九项

### 1. 限定词必须绑到运行时来源

判据里每一个「本周 / 本月 / 最近 / 该用户 / 该动作 / 前 N 条」，在同一行写出它在运行时从哪里来。

> 反例：判据和评测标准答案都写「本周共记录 N 次训练」，客户端默认发的是近 30 天。数字是真的，限定词是假的。单测、评测、E2E、审查全部放行。

### 2. 每条判据写出一个「通过它但仍然错」的实现

写不出来，说明判据要么太模糊、要么覆盖面太窄，回去改。写得出来，就把那个实现补成一条负向断言。

### 3. 度量必须给出算法

「不超过 30 行」有三种算法：新增行、新增加删除、净增。不指定算法，执行方会默认选对自己最有利的那种，而且他不觉得自己在作弊。

- 行数 → `git diff --numstat` 的 additions + deletions
- 「快速失败」→ 阈值必须严格小于被替换实现的真实耗时（阈值 130 秒、旧实现耗满 120 秒，这条断言对任何行为都为真）
- 耗时/条数 → 指定命令和取数位置

### 4. 允许改动的文件必须枚举

写出完整路径清单，分别检查 tracked 与 untracked：

- 已冻结 candidate：`git diff --name-only <baseline-SHA>..<candidate-SHA>`。
- 浮动工作区预查：`git diff --name-only <baseline-SHA>`。
- 未跟踪文件：`git ls-files --others --exclude-standard`。

将适用命令的结果取并集，再与允许清单逐字比较。`WORKTREE` 不是 Git revision，不能写进 revision range。

> 反例：判据写「只包含本次任务涉及的文件」。上一批未提交的 447 行 CSS 也「涉及本任务」，于是被判达成，本批 80 行的改动报成了 800 行。

### 5. 每条判据必须标验证类型

把判据分成三类，不用机器结果冒充人工裁决：

- `机器判据`：写明命令、取数位置、算法与期望结果。
- `人工判据`：写明验收者、操作步骤和观察点；执行方永远不得自行判「达成」。
- `尚不可验证`：写明缺少的环境、数据或授权，只能报告「未验证」。

「体验流畅」这类表述先尽量改成可观察步骤；无法完全机器化时保留为人工判据，不得为了自动绿灯删掉。

### 6. 层级必须点名

写「HTTP 层覆盖 422」会被 service 层单测冒充。要哪一层就写到可执行：对 `<具体路由>` 发真实请求，断言状态码和 error 结构。

同理：真库 ≠ mock，真实客户端路径 ≠ 服务端直连探针，SQL 字符串断言 ≠ Postgres 实际执行结果。

### 7. 不许从属性推行为

「是原生 button，所以键盘可用」不成立。要键盘就逐个写：Tab 能到达、Enter 触发后的状态、Space 触发后的状态、URL 变化。没有逐项记录就只能写「未验证」。

### 8. 判据之间不许打架

冻结前通读一遍找冲突。「本批不许提交」和「独立核验需要固定 SHA」同时存在时，批次结构上不可能完成——先解决冲突再冻结。

### 9. 面向自由输入的任务必须覆盖真实输入分布

当任务涉及搜索、分类、自然语言、路由或其他自由输入时，只有正例的判据集会一致地绿灯。至少补三类：

- 真实常用简写（用户真会打的「周报」，不是你以为他会打的完整句）
- 邻域反例（「上周我女朋友生气了」「小组数量」「模型训练」「医疗器械」——和正例共享字符但不该命中的）
- 无覆盖话题（知识库里没有的主题必须澄清或拒答，不许自信错答）

## 输出格式

```
contract SHA：
baseline SHA：
candidate SHA：（开工前为空）
契约文件路径：
允许改动文件（逐个列出）：

判据 1：<机器 / 人工 / 尚不可验证> · <可证伪的一句话>
  度量：<命令 / 取数位置 / 算法>
  已知的假绿灯：<一个通过它但仍然错的实现>
判据 2：...

冲突检查：已通读，无冲突 / 发现冲突 <描述>
限定词检查：<逐个列出判据里的限定词及其运行时来源>
```

## 什么时候不用

一晚上内、单模块、可回滚且不涉及安全、数据、权限或发布的小活。写一句可证伪的判据就够；风险高时由风险覆盖规模，仍走完整检查。
